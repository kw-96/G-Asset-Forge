# 需求文档

## 项目介绍

H5 模式隔离项目旨在实现 G-Asset Forge 编辑器中设计模式和 H5 模式的彻底隔离。当前系统存在两种模式共享状态、画布状态污染、项目数据混合等问题，导致项目打开时出现状态冲突和数据不一致。本项目将基于同一个编辑器核心，通过重构架构实现模式特定的状态管理、数据格式和 UI 组件，确保设计项目和 H5 项目在各自独立运行时保持完全的状态隔离。每个项目文件对应单一模式（设计模式或 H5 模式），不支持模式间切换。

## 需求列表

### 需求 1: 项目类型识别和模式配置

**用户故事:** 作为系统架构师，我希望系统能够根据项目类型自动配置对应的编辑模式，以便确保每个项目在正确的模式下运行。

#### 验收标准 1.1

1. 当创建设计项目时，系统应当标记项目类型为'design'并配置编辑器为设计模式
2. 当创建 H5 项目时，系统应当标记项目类型为'h5'并配置编辑器为 H5 模式
3. 当打开项目时，系统应当根据项目数据中的类型标识或 H5Container 存在性自动识别项目类型
4. 当项目类型确定后，系统应当配置编辑器核心使用对应模式的功能和服务
5. 当项目运行时，系统应当确保项目始终在其对应的模式下运行，不允许模式切换
6. 当项目保存时，系统应当保持项目类型标识的一致性
7. 当项目类型识别失败时，系统应当提供明确的错误信息和默认处理方案

### 需求 2: 设计模式项目隔离

**用户故事:** 作为设计师，我希望设计项目拥有独立的状态管理和 UI 环境，以便专注于图形设计工作而不受 H5 项目影响。

#### 验收标准 2.1

1. 当打开设计项目时，系统应当配置编辑器核心使用标准的图形编辑功能
2. 当设计项目运行时，系统应当显示设计模式 UI 布局（页面面板、图层面板、属性面板）
3. 当设计项目运行时，系统应当使用标准的画布状态管理，支持多页面和图层操作
4. 当设计项目处理数据时，系统应当使用标准的编辑器数据格式，不包含 H5 特定元素
5. 当设计项目保存状态时，系统应当维护标准的编辑器状态和历史记录
6. 当设计项目操作页面时，系统应当正确管理多页面状态和图层结构
7. 当设计项目关闭时，系统应当完全清理所有设计相关的状态，不影响后续 H5 项目

### 需求 3: H5 模式项目隔离

**用户故事:** 作为 H5 设计师，我希望 H5 项目拥有独立的状态管理和 UI 环境，以便专注于长图设计工作而不受设计项目影响。

#### 验收标准 3.1

1. 当打开 H5 项目时，系统应当配置编辑器核心并初始化 H5Service 实例
2. 当 H5 项目运行时，系统应当显示 H5 模式 UI 布局（内容块面板、图层面板、H5 属性面板）
3. 当 H5 项目运行时，系统应当使用 H5Service 管理 H5Container 和内容块状态
4. 当 H5 项目处理数据时，系统应当使用包含 H5Container 的专门数据格式
5. 当 H5 项目保存状态时，系统应当维护 H5 特定的状态和内容块历史记录
6. 当 H5 项目管理内容块时，系统应当正确处理内容块的顺序、布局和属性
7. 当 H5 项目关闭时，系统应当完全清理 H5Service 和相关资源，不影响后续设计项目

### 需求 4: 项目数据格式隔离

**用户故事:** 作为项目管理员，我希望不同类型的项目数据完全隔离存储，以便确保数据完整性和项目类型的独立性。

#### 验收标准 4.1

1. 当保存设计项目时，系统应当使用标准的编辑器数据格式，确保不包含 H5 特定元素
2. 当保存 H5 项目时，系统应当使用包含 H5Container 和内容块的专门数据格式
3. 当加载项目时，系统应当根据项目数据中是否包含 H5Container 准确识别项目类型
4. 当项目数据序列化时，系统应当确保 H5 项目数据包含完整的容器和内容块信息
5. 当项目数据反序列化时，系统应当正确恢复 H5Container 及其子元素结构
6. 当项目数据格式不匹配时，系统应当提供清晰的错误提示和处理机制
7. 当项目数据验证时，系统应当检查数据格式是否符合对应项目类型的要求

### 需求 5: 状态管理隔离

**用户故事:** 作为开发者，我希望每种项目类型拥有独立的状态管理系统，以便确保状态变更不会影响其他类型的项目。

#### 验收标准 5.1

1. 当设计项目运行时，系统应当维护标准的编辑器状态（选择、工具、视口、页面等）
2. 当 H5 项目运行时，系统应当维护 H5 特定状态（当前容器、选中内容块、布局设置等）
3. 当项目关闭时，系统应当保存当前项目状态并完全清理状态管理器和服务实例
4. 当状态变更时，系统应当只影响当前项目的状态，不污染全局状态
5. 当状态持久化时，系统应当将项目状态与项目数据一起正确存储
6. 当状态恢复时，系统应当根据项目类型恢复对应的状态和服务
7. 当状态验证时，系统应当检查状态的完整性和与项目类型的一致性

### 需求 6: 初始化流程隔离

**用户故事:** 作为系统用户，我希望不同类型项目的初始化过程完全独立，以便避免初始化冲突和状态污染。

#### 验收标准 6.1

1. 当系统启动时，项目管理器应当根据项目类型确定正确的初始化流程
2. 当初始化设计项目时，系统应当按正确顺序创建标准编辑器组件和状态管理器
3. 当初始化 H5 项目时，系统应当按正确顺序创建 H5Service、H5Container 和相关 UI 组件
4. 当项目初始化失败时，系统应当提供错误恢复机制和清晰的错误信息
5. 当项目初始化完成时，系统应当验证所有组件的正确性和状态一致性
6. 当项目加载时，系统应当根据项目数据中的 H5Container 标识选择正确的初始化流程
7. 当初始化过程中出现异常时，系统应当安全回退并清理已创建的资源

### 需求 7: UI 组件和服务隔离

**用户故事:** 作为界面设计师，我希望每种项目类型拥有独立的 UI 组件和服务系统，以便提供项目类型特定的用户体验。

#### 验收标准 7.1

1. 当设计项目激活时，系统应当显示设计模式布局（页面面板、图层面板、属性面板）
2. 当 H5 项目激活时，系统应当显示 H5 模式布局（内容块面板、图层面板、H5 属性面板）
3. 当任何项目运行时，系统应当共享同一套工具栏（toolbar）和悬浮操作按钮
4. 当项目关闭时，系统应当清理项目特定的 UI 组件并正确销毁服务实例
5. 当图层面板在不同项目类型中使用时，系统应当根据项目类型显示对应的内容（设计元素或 H5 内容块及其子元素）
6. 当 UI 组件交互时，系统应当调用对应项目类型的事件处理器和服务方法
7. 当 UI 组件销毁时，系统应当清理项目特定的事件监听器、定时器和服务资源
